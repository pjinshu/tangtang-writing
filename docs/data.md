# 实测数据与核验方式

## 数据口径说明

以下数据来自开发团队的内部实测记录，指的是**用本产品的流程完成的作品**。

**不等同于对使用者的效果承诺。** 写作结果与题材、作者参与程度、平台标准都有关系。

## 一致性核验方式

不是"感觉不错"，而是可逐项核对：

| 核验项 | 判定方式 |
|---|---|
| 章题对应 | 每章标题是否等于分章规划中的标题 |
| 伏笔回收 | 伏笔台账登记的每一条，回收状态是否正常 |
| 字数达标 | 每章有字数下限，不足即拦 |
| 跨卷收束 | 本卷该讲完的事是否讲完 |

全部由**程序逐项判定**，不依赖模型的自我评价。

---

## 文风一致性

长篇另一个容易出问题的地方是笔调漂移：单看一章没问题，连读五章会发现像几个人接力写的。

做法：开书时锚定这本书的**叙述声音、句式习惯、对话节奏、文字质感**，之后每一章沿用同一套标准。

在这部 260 章的作品里，全程文风与文笔未出现漂移。

## 测试规模

- 产品落地前的样张测试：**四五十部小说**
- 本地化阶段的样张：**将近上百部**
- 专门测试项：在每个环节提修改意见（对大纲提、对初稿提），要求加入人工设计的剧情或人物设定 —— 产出与预期吻合，说明作者可随时介入
